# Schema of `<output_folder>/reports/drift.md`

Specs health dashboard — shows for each spec how synchronized it is with current code.

Maintained by Keeper in `after` mode. Can be read by humans and parsed by the `npx aegis-spec drift-check` command (CI gate).

---

## File structure

```markdown
# Drift Dashboard

Last update: YYYY-MM-DD HH:MM (UTC)
Generated by: aegis-keeper v2.0.0

## Summary

- Total specs: [N]
- 🟢 resolved: [N] ([P]%)
- 🟡 stale: [N] ([P]%)
- 🔴 pending: [N] ([P]%)

## Specs

| Spec | Last sync | Status | Confidence distribution | Suggested action |
|---|---|---|---|---|
| `specs/sdd/authentication.md` | 2026-04-29 14:32 | 🟢 resolved | 🟢 80% / 🟡 18% / 🔴 2% | — |
| `specs/sdd/billing.md` | 2026-04-25 09:10 | 🟡 stale | 🟢 75% / 🟡 20% / 🔴 5% | Run `/aegis-archaeologist` |
| `specs/sdd/notifications.md` | 2026-04-29 14:25 | 🔴 pending | 🟢 60% / 🟡 30% / 🔴 10% | Run `/aegis-keeper after` |
```

---

## Fields

### `Spec`
Path relative to `<output_folder>/`. Usually in `specs/sdd/`, but can include `specs/openapi/`, `specs/database/`, etc.

### `Last sync`
UTC timestamp of the last time Keeper updated (or confirmed consistency) for this spec. Format: `YYYY-MM-DD HH:MM`.

### `Status`
One of:

| Value | Meaning | When to apply |
|---|---|---|
| `🟢 resolved` | Spec synchronized with current code | After processing changes or after confirming that recent changes didn't affect spec |
| `🟡 stale` | No sync for >7 days and code was modified in mapped paths | Detected by hooks (in `after` mode) or by periodic scan |
| `🔴 pending` | Change detected but not yet processed by Keeper | Hooks mark as `pending` at edit time; Keeper `after` changes to `resolved` |

### `Confidence distribution`
Percentage of 🟢/🟡/🔴 statements in the spec, recomputed when spec is updated.

Calculation: count 🟢, 🟡, 🔴 emojis in spec, divide by total, round to integer.

### `Suggested action`
Free text — usually the recommended slash command:
- `Run /aegis-keeper after` (status `pending`)
- `Run /aegis-archaeologist` (structural drift or stale)
- `Run /aegis-reviewer` (multiple specs affected)
- `Run /aegis-data-master` (schema change)
- `—` (status `resolved`, no action)

---

## Status transition rules

```
[new spec file created]
        │
        ▼
   🟢 resolved
        │
        │ (hook detects edit in mapped file)
        ▼
   🔴 pending
        │
        │ (Keeper after processes)
        ▼
   🟢 resolved
        │
        │ (>7 days without sync + unprocessed edits detected)
        ▼
   🟡 stale
        │
        │ (Keeper after or Archaeologist processes)
        ▼
   🟢 resolved
```

---

## Auto-cleanup

To prevent unlimited growth:

- Specs `resolved` for >30 days **remain** in dashboard (last sync is useful info)
- Lines for deleted specs (spec file no longer exists) are removed after 60 days
- No drift.md rotation — it's the current state, not history

Change history lives in `<output_folder>/changelog/YYYY-MM-DD.md`.

---

## Parsing by `drift-check` CLI

The `npx aegis-spec drift-check` command parses this file looking for status emoji in the `Status` column:

- Counts rows with `🔴 pending` → `pendingCount`
- Counts rows with `🟡 stale` → `staleCount`
- Counts rows with `🟢 resolved` → `resolvedCount`

Exit codes:
- `0` if `pendingCount == 0` (clean)
- `1` if `pendingCount > 0` (unresolved drift — CI fails)
- `2` if `drift.md` doesn't exist (instructs to run `/aegis` first)

Optional filters:
- `--severity high`: count only `pending`
- `--severity medium`: count `pending + stale`
- `--severity low`: ignore all (always exit 0 — report only)
